本目录是实现 ARM64 原生槽位服务的**正向开发规格**，供开发者与 AI 助手
直接使用。它只描述「应当实现什么」，不记录分析过程。

分析记录不在本交付目录内，不参与开发流程。

## 按任务的阅读路径

### 任务 A：实现 CLI 宿主（`cli-host`）

1. `02` 全文——帧协议是它的唯一输入输出；
2. `03` 3.1–3.5、3.7——上游请求与流处理；
3. `07` 7.1、7.2、7.7——模式开关与进程环境；
4. `06` 6.4——每请求读取凭据；
5. `04` A、B、C、D、E、F 组。

产出：一个只读 stdin 帧、写 stdout 帧、调用上游的进程。

### 任务 B：实现内核（`kin-kernel`）

1. `05` 5.1、5.4、5.5、5.6、5.7、5.9——进程模型、内部接口、调度、
   宿主生命周期、看门狗、资源限制；
2. `05` 5.2——对外 HTTP 接口与请求校验；
3. `02` 2.5、2.6——内核侧需要发出的信号；
4. `06` 6.2、6.3——配置与环境变量；
5. `04` A、D、E、G 组。

产出：一个监听 Unix socket、管理槽位代次、转发请求的进程。

### 任务 C：实现登录与运维命令

1. `07` 7.3、7.4——命令分派、`auth login`、`setup-token`；
2. `07` 7.5——`-p hello` 与 `/usage`；
3. `06` 6.4.4——凭据刷新分工，不要自己刷新；
4. `04` H 组。

产出：控制面初始化槽位时需要的四个入口。

### 任务 D：实现主 API

1. `05` 5.2——路由、请求校验、OpenAI 兼容层；
2. `05` 5.3.1——直连上游的构造、解析与错误码；
3. `03` 3.3.1 开头的例外说明——主 API 不加工 system；
4. `04` G 组。

产出：`provider=anthropic_api` 时的 `/v1/messages` 与
`/v1/chat/completions`。

## 建议的开发顺序

```text
1. CLI 宿主运行期        （任务 A）
2. 内核运行期            （任务 B）
3. system 生成与 beta    （03 3.2、3.3.1）
4. 登录与 print 模式     （任务 C）
5. 主 API                （任务 D）
6. 全量验收              （04）
```

前两步完成后即可替换槽位运行期；第三步决定行为是否等价；
第四步决定控制面能否完成初始化。

## 判定完成

只有同时满足以下条件才算完成：

- `04` 的 A、B、C、D、G 组全部通过；
- E 组无死锁、无跨槽位影响；
- F 组上游请求与客户端请求语义一致；
- H 组四个入口可用；
- 连续运行 24 小时无宿主重启、无连接泄漏。
